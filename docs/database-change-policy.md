# 数据库变更策略

1. 每次结构变更必须提交可审阅、可回滚说明的 migration。
2. 生产环境只运行 `prisma migrate deploy`，禁止 `db push` 与 synchronize。
3. 不修改已发布表名、字段名或字段语义；优先新增字段、表、索引。
4. 破坏性变更采用扩展—迁移数据—切换读写—清理四阶段。
5. 新必填字段先允许空值并回填，再增加约束。
6. JSON 结构变化必须提升内部 schema 版本并保留兼容读取。
7. migration 前备份，发布后校验记录数、外键、唯一索引及抽样导出。
8. 业务数据默认软删除；永久清理由人工批准的维护任务完成。
9. migration 与对应应用版本一起评审，不在程序启动时自动改库。
